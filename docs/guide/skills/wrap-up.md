# 任务收尾

`wrap-up` 在一个任务结束时完成收尾：校验、沉淀结论、只提交本任务的改动，最后归档当前会话。下一个任务开新会话，只靠仓库本身就能接上。

| 调用                     | 触发   | 来源                                                                   |
| ------------------------ | ------ | ---------------------------------------------------------------------- |
| `/wrap-up [push] [keep]` | 仅手动 | [独立 Skill](https://github.com/YunYouJun/ai/tree/main/skills/wrap-up) |

## 为什么需要它

「一个任务一个会话」能让上下文保持干净，也更省 Token，原因见[最佳实践](/claude-code/best-practices#一个任务一个会话)。但会话一归档，里面的信息就不会再被读到：没写进仓库、memory 或 Issue 的结论，下一个会话不会知道。

所以收尾的重点在归档之前：确认提交范围、记下决策和后续事项。这几步每次都要做，顺序也固定，适合封装成 Skill。只做 `git commit` 不需要 Skill，直接说「commit」就行。

## 安装

```bash
npx skills add YunYouJun/ai --skill=wrap-up
```

## 使用示例

```text
/wrap-up            # 提交但不推送，然后归档
/wrap-up push       # 提交并推送，然后归档
/wrap-up keep       # 只收尾提交，保留会话（例如还要等 Review）
/wrap-up 把放弃插件市场的原因记进 plan
```

## 执行内容

1. **划定范围**：对照本次对话，把改动分为「本任务」和「无关」两类，只按路径暂存本任务的改动，不使用 `git add -A`；
2. **检查敏感文件**：不提交 `.env`、密钥和本地配置；
3. **校验**：代码有改动时，运行受影响范围的 lint、类型检查和测试，失败则不提交、不归档；
4. **沉淀结论**：设计决策和踩坑写进仓库文档，跨任务的偏好写进 memory，未完成的事项写成 TODO、Issue 或新会话；
5. **提交**：遵循仓库的提交约定，不相关的改动拆成多个 commit；只有传入 `push` 时才推送；
6. **归档前检查**：以下情况不归档：worktree 中还有未提交改动、还有后台任务在运行、PR 正在等待 Review；
7. **汇报并归档**：列出提交、沉淀内容、未处理的无关改动和后续事项，最后归档当前会话。

## 不同环境的差异

- **Claude Code 桌面版**：通过会话管理工具归档当前会话，归档后对话结束，可以在 Archived 列表中恢复；
- **CLI 与其他 Agent**：没有「归档」概念，Skill 完成提交后会提示用 `/clear` 或新开会话。

走 PR 流程的任务，也可以在 Settings → Claude Code 中开启「PR 合并或关闭后自动归档会话」，代替手动归档。
